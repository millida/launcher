# Millida Launcher

Десктопный лаунчер Minecraft для Windows, macOS и Linux. Ставит версии игры,
загрузчики модов, сами моды и модпаки, подбирает и скачивает Java, следит за
профилями, мирами и скинами — всё в одном приложении.

Ядро написано на Rust и работает как отдельный слой: установка, запуск игры,
работа с файлами и токенами живут в `src-tauri`, интерфейс — React поверх
IPC-команд ядра. Подробный разбор устройства — в [ARCHITECTURE.md](ARCHITECTURE.md).

- Приложение: Tauri 2 (Rust) + React 19 + TypeScript + Vite
- Пакетный менеджер: bun
- Лицензия: GPL-3.0-only

## Для кого

Для игроков, которым нужен один клиент вместо связки «лаунчер + браузер +
архиватор»: поиск модов, установка сборки, выбор Java, миры и бэкапы делаются
из интерфейса. И для тех, кто предпочитает лаунчер с открытым кодом, где видно,
что именно запускается и куда уходят данные.

Чем отличается от привычных вариантов:

- Токены доступа никогда не попадают в вебвью — их держит и применяет только
  Rust-ядро (см. [Безопасность](#безопасность)).
- Каталоги Modrinth и CurseForge в одном окне, включая карты, ресурспаки,
  шейдеры и датапаки, а не только моды.
- Импорт существующих сборок из других лаунчеров без ручного копирования папок.
- Всё скачанное исполняемое (JRE, установщики загрузчиков, библиотеки игры)
  сверяется по хешу до запуска.

## Возможности

**Версии и загрузчики.** Полный список версий из манифеста Mojang, включая
снапшоты и старые релизы. Загрузчики: Fabric, Quilt, Forge, NeoForge. Версию
загрузчика можно закрепить вручную или взять последнюю подходящую.

**Каталоги контента.** Modrinth и CurseForge: моды, модпаки, ресурспаки,
шейдеры, датапаки и карты. Установка идёт в конкретную сборку, ставится и
проверка обновлений — для одного файла или сразу для всего списка. Локальные
файлы можно добавить вручную, а собранную сборку выгрузить в `.mrpack`.

**Профили (сборки).** Отдельная папка игры на сборку, группы, иконки и обложки,
дублирование, переименование, лимит памяти и свои аргументы JVM, размер окна,
свой путь к Java, ремонт повреждённой установки.

**Java.** Ядро само определяет нужный мажор по версии игры, скачивает JRE
Eclipse Temurin через API Adoptium и проверяет sha256 архива. Можно указать
свой путь к Java и проверить его прямо из настроек. Внутри Flatpak берётся JDK
из SDK-расширения, ничего не качается.

**Импорт из других лаунчеров.** Сканируются установки Prism Launcher, MultiMC,
ATLauncher, GDLauncher, CurseForge, Modrinth App и лаунчеров, работающих с общей
`.minecraft` (включая TLauncher), в том числе на несистемных дисках. Отдельно
поддерживается импорт файла сборки — `.mrpack` и архивы CurseForge.

**Аккаунты.** Вход по лицензии Microsoft (device flow, цепочка Xbox Live → XSTS →
Minecraft Services) и вход в аккаунт Millida. Несколько аккаунтов одновременно,
переключение без повторного входа, офлайн-режим.

**Скины и плащи.** Локальная библиотека скинов и плащей, загрузка скина и смена
плаща на лицензионном аккаунте через Minecraft Services, предпросмотр в 3D.
Для скинов Millida на модовых сборках ядро подключает authlib-injector и, при
необходимости, CustomSkinLoader.

**Миры и серверы.** Список миров сборки, удаление, бэкап мира в zip, счётчик и
папка скриншотов. Серверы: чтение и правка `servers.dat`, пинг сервера,
быстрый вход в мир или на сервер через Quick Play.

**Логи и падения.** Вывод игры пишется в отдельный лог запуска, падения
распознаются и показываются с отчётом, лог можно выгрузить одним действием.

**Discord Rich Presence.** Статус в Discord с текущей сборкой. Идентификатор
приложения переопределяется переменной `MILLIDA_DISCORD_APP_ID`.

**Автообновление.** Обновление скачивается в фоне и ставится при выходе. Если
штатный апдейтер не справился, включается запасной путь в ядре
([selfupdate.rs](src-tauri/src/engine/core/selfupdate.rs)), который проверяет ту
же minisign-подпись тем же ключом, но своим кодом.

**Панель хостинга.** Управление серверами Millida Hosting: консоль в реальном
времени, файлы, мир, сеть, доступы, расписание, тариф. Работает с аккаунтом
Millida и требует сервисов `api.millida.net`.

**Мелочи.** Трей и сворачивание вместо закрытия, deep-link `millida://`,
своя тема и акцент, видео- и картиночные обои, музыка и звуки интерфейса,
статистика наигранного времени.

### Что зависит от сервисов Millida

Установка игры, загрузчики, Java, Modrinth и работа с файлами не требуют наших
серверов. К `api.millida.net` обращаются: вход Millida, друзья и чат, скины
Millida, рейтинг серверов, панель хостинга и прокси к API CurseForge (ключ
CurseForge держится на сервере; при недоступности прокси используется публичное
зеркало). В форке эти разделы либо останутся пустыми, либо их нужно переключить
на свой бэкенд.

## Сборка из исходников

### Требования

- [Rust](https://rustup.rs) stable
- [bun](https://bun.sh)
- Windows: Visual Studio Build Tools с рабочей нагрузкой C++ (MSVC) и WebView2
  Runtime (в Windows 11 уже есть)
- macOS: Xcode Command Line Tools (`xcode-select --install`)
- Linux: `libwebkit2gtk-4.1-dev`, `libappindicator3-dev`, `librsvg2-dev`,
  `patchelf`, `libxdo-dev`, `libssl-dev`, `build-essential`, `file`, `wget`

### Запуск

```bash
bun install          # зависимости + подтягивание медиа (см. ниже)
bun run tauri dev    # приложение целиком: Rust-ядро и фронтенд
bun run tauri build  # установщики под текущую платформу
```

Прочие скрипты (`package.json`):

| Скрипт | Что делает |
| --- | --- |
| `bun run dev` | только веб-фронтенд на `http://localhost:5173`, без ядра |
| `bun run typecheck` (`lint`) | `tsc -b` в строгом режиме |
| `bun run build:web` | typecheck, сборка фронта в `dist/` и проверка собранного бандла |
| `bun run test` | тесты фронтенда (`bun test`) |
| `bun run build:fast` | сборка приложения без LTO — заметно быстрее, бинарник крупнее |

Rust-часть проверяется своими средствами из `src-tauri`:

```bash
cd src-tauri
cargo test
cargo clippy --all-targets -- -D warnings
```

Форматтер не используется, качество кода держит clippy.

Фронтенд открывается и в обычном браузере без Tauri: разделы, которым нужно
ядро, показывают заглушки.

## Вход по лицензии Microsoft: своей сборке нужна своя регистрация Azure

Client_id приложения Azure вшивается в бинарник на этапе компиляции из
переменной окружения `MILLIDA_MS_CLIENT_ID`
([src-tauri/src/engine/accounts/microsoft.rs](src-tauri/src/engine/accounts/microsoft.rs)).
В репозитории лежит запасной client_id, чтобы сборка из исходников работала
сразу, — но это регистрация Millida.

```bash
MILLIDA_MS_CLIENT_ID=<client-id-твоего-приложения-Azure> bun run tauri build
```

Если этого не сделать, форк делит лимиты и репутацию чужого приложения:
ограничения Microsoft считаются на client_id, поэтому нагрузка форка отражается
на пользователях оригинала и наоборот, а отозванная или заблокированная
регистрация ломает вход сразу всем. Публикуемым сборкам нужна собственная
регистрация в Azure — приложение с поддержкой device code flow и разрешением
`XboxLive.signin`.
